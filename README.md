# HashForensics Agent · 哈希取证迷你智能体

一个用 **Python 标准库**写成的哈希取证助手：把「哈希识别、正向计算、查表反查、完整性校验、
内容去重、取证问答」包装成自然语言对话，并支持**本地大模型**驱动理解层。

> **核心特点**：单文件、零第三方依赖、可完全离线运行、全程审计留痕。
> 理解层可选接入大模型（云端 API 或本地 llama.cpp），也可以在纯规则模式下工作。

### 字典规则引擎（v2.3 新增）

词表导入时可加变形规则，弱口令命中率大幅提升（实测：20 个 std 变体裸查 1 命中 → std 档 20 全命中）：

```
你说> 建表 wordlist.txt rules=std
你说> 解密 <某变形哈希>
```

- `rules=min`：最小变形（基础变体）
- `rules=std`：标准变形（大小写 / leet / 数字年份后缀，单条约 ×210）
- `rules=max`：最大变形（约 ×840，压测 10 万条词表内存恒定）

## 它能做什么

### 六类意图

| 意图 | 说法示例 | 行为 |
|---|---|---|
| **识别** | `这是什么哈希 e10adc3949ba59abbe56e057f20f883e` | 按长度/字符集判断算法类型，给出该算法的安全评价 |
| **正向计算** | `加密：062481，sha-256`<br>`算一下hello的md5`<br>`062481的sm3是多少` | 按指定算法计算哈希，**并自动写入本地对照表** |
| **查表反查** | `解密 6fca16b5…`<br>`帮我看看这串能不能还原` | 依次查询：本地对照表 → 内置样本库 → 图形密码全量表 |
| **完整性校验** | `校验 hello.txt` | 计算双哈希（MD5+SHA-256）并与记录比对 |
| **内容去重** | `对 screening 去重` | 按 SHA-256 分组，找出内容完全相同的文件 |
| **知识问答** | `为什么要双哈希`<br>`加盐到底有什么用`<br>`MD5能不能解密` | 从内置 FAQ 语料作答 |

### 支持的算法

| 算法 | 正向计算 | 查表反查 | 说明 |
|---|:---:|:---:|---|
| MD5 | ✅ | ✅ | 128 位，已被碰撞攻破，仅作快速筛查 |
| SHA-1 | ✅ | — | 160 位，已可碰撞，校验场景应淘汰 |
| SHA-256 | ✅ | ✅ | 256 位，完整性校验首选 |
| SHA-512 | ✅ | — | 512 位强哈希 |
| **SM3** | ✅ | — | 国密杂凑算法（GB/T 32905），纯 Python 实现 |
| bcrypt | 识别 | ⛔ **主动劝退** | 慢哈希自带盐，查表无效 |

### 两个特色行为

**① 慢哈希劝退**——遇到 bcrypt 这类慢哈希，agent 不会傻乎乎地开始爆破，而是直接给出成本评估：

```
你说> 帮我破解 $2b$12$KIX/DeWw5Z5pXbH9Qz1eeOsF7kQf9XqWYh2m1Z0VZ8vJ3xWq5yZzW
  [crack] 未成功
  说明：bcrypt 是慢哈希且自带盐：预计算表无效，盲目穷举性价比极低。
        建议只做已知口令定向尝试，或放弃爆破改查其他证据。
```

**② 组合意图**——一句话触发多步流水线：

```
你说> 破解e10adc3949ba59abbe56e057f20f883e再校验是不是同一个文件
  [crack_then_verify] 成功
  结果：原文=123456；破解出的原文与演示样本不一致 → 非同一内容
```

## 架构与原理

### 四层单循环

```
        ┌─────────────────────────────────────────────────┐
你的话 → │ ① 感知层  自然语言 → {action, params}            │
        │           --llm：大模型 function calling         │
        │           默认：正则规则表（确定性、可审计）        │
        └────────────────────┬────────────────────────────┘
                             ↓
        ┌─────────────────────────────────────────────────┐
        │ ② 决策层  按算法/场景选路                         │
        │           快哈希 → 查表                          │
        │           慢哈希 → 劝退 + 成本评估                 │
        │           组合句 → 拆成多步                       │
        └────────────────────┬────────────────────────────┘
                             ↓
        ┌─────────────────────────────────────────────────┐
        │ ③ 行动层  调用 toolkit.py 的真实函数              │
        │           模型只出主意，动手的永远是本地代码        │
        └────────────────────┬────────────────────────────┘
                             ↓
        ┌─────────────────────────────────────────────────┐
        │ ④ 反馈层  结果 + 方法 + 可信度 + 审计日志          │
        └─────────────────────────────────────────────────┘
```

**为什么这样设计**：智能体现在决策层（可替换），安全性体现在行动层（白名单固定）。
升级理解层不需要改行动层一行代码——这就是规则版和 LLM 版能共存的原因。

### Agent 是什么（原理说明）

智能体（agent）的经典定义是**能感知环境、自主决策、采取行动以达成目标的实体**——
三个要素是「感知、决策、行动」，其中并不包含「必须使用大模型」。

按能力谱系划分：

```
简单反射 agent（if-then 规则）        ← 本项目的规则模式
基于模型的反射 agent
目标驱动 agent（搜索规划）
效用驱动 agent（权衡取舍）
学习 agent（自我改进）
……
LLM agent（用大模型充当决策内核）      ← 本项目的 --llm 模式
```

大模型只是**决策器的一种实现方式**，不是 agent 的准入条件。本项目同时提供两种决策内核：

| 模式 | 决策方式 | 优点 | 代价 |
|---|---|---|---|
| 规则模式（默认） | 正则规则表 | 零依赖、毫秒级、行为确定、完全可审计 | 泛化差，没写过的说法听不懂 |
| LLM 模式（`--llm`） | 大模型 function calling | 口语自由、能处理没见过的表述 | 需要模型服务、有延迟 |

两者输出**同一种结构**给行动层，所以可以随时切换、失败自动降级。

## 接入大模型（可选）

### 方式一：本地模型（推荐，数据不出本机）

以 llama.cpp 为例，先把模型跑成 OpenAI 兼容服务：

```bash
llama-server.exe -m D:\AI\Qwen3.5-9B-Q4_K_M.gguf --port 8600 --gpu-layers 99
```

然后设置环境变量并启动 agent：

```powershell
$env:LLM_API_BASE = "http://127.0.0.1:8600/v1"
$env:LLM_API_KEY  = "local"          # 本地服务不校验，但需非空
$env:LLM_MODEL    = "qwen3.5-9b"
python agent.py --llm
```

Ollama、LM Studio、vLLM 等同理，它们都提供 OpenAI 兼容端点：

```powershell
# Ollama 示例
$env:LLM_API_BASE = "http://localhost:11434/v1"
$env:LLM_MODEL    = "qwen2.5:7b"
```

### 方式二：云端 API

任何 OpenAI 兼容接口都能直接用（DeepSeek / OpenAI / 通义 / Kimi / 豆包…）：

```powershell
$env:LLM_API_BASE = "https://api.deepseek.com"
$env:LLM_API_KEY  = "sk-你的key"
$env:LLM_MODEL    = "deepseek-chat"
python agent.py --llm
```

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `LLM_API_BASE` | `https://api.deepseek.com` | 接口地址，**不要带末尾斜杠** |
| `LLM_API_KEY` | 无 | 有值才会启用 LLM 模式 |
| `LLM_MODEL` | `deepseek-chat` | 模型名称 |

### 安全边界（重要）

接大模型时，**模型只做一件事**：把自然语言翻译成结构化指令。

```json
{"action": "hash_compute", "content": "062481", "algo": "SHA-256"}
```

然后由本地代码做三件事：

1. **白名单校验**——action 必须是 8 个已知意图之一，否则直接拒绝；
2. **本地执行**——模型无法直接执行任何命令、无法读写文件、无法访问网络；
3. **审计留痕**——每次调用都写日志。

发送给 API 的只有**你的指令文本本身**；文件内容、文件路径、对照表都留在本地。
用本地模型时，连指令文本也不出机器。

### 失败降级

以下任一情况会自动回退到规则模式，服务不中断：

- 未设置 `LLM_API_KEY`
- API 超时（默认 60 秒）或报错
- 模型输出的 JSON 无法解析
- 模型给出的 action 不在白名单内

## 本地对照表机制

### 它是什么

`hash_table.json`——一张「哈希值 → 原文」的映射表，由 agent 自己攒出来：

```json
{
  "MD5": {
    "aa357ade530b855c0c6c7598481f46af": "062481"
  },
  "SHA-256": {
    "6fca16b5abe708c25bd4a4afc91801b38ca1ffc5853020a8f6559e5f3ee5ff37": "062481"
  }
}
```

### 怎么攒

**方式一：逐条累积**——任何正向计算都会自动入表

```
你说> 加密：062481，sha-256      ← 自动写入 MD5 + SHA-256 两张索引
```

**方式二：词表批量导入**——准备一个每行一个候选明文的 txt

```bash
# wordlist.txt 内容示例：
# 123456
# password
# 062481
```

```
你说> 建表 wordlist.txt
  [build_table] 成功
  结果：导入 3 条，对照表现有 4 条（MD5+SHA-256 双索引）
```

### 查表顺序

```
① 本地对照表（含历史计算结果与导入的词表）
   ↓ 未命中
② 内置样本库（演示用已知值）
   ↓ 未命中
③ 图形密码全量表（389,112 种，约 1~2 秒穷举）
   ↓ 未命中
④ 如实报告失败 + 给出下一步建议
```

### 必须理解的一点

**这是查表，不是解密。** 哈希是单向压缩映射，信息在运算中被不可逆丢弃，数学上不存在反推。
所谓「查表命中」的准确含义是：

```
建表时：对候选明文逐个正向计算 → 存进表里
查询时：拿你的哈希去表里比对 → 命中就返回当年算过的那个明文
```

**命中前提是原文在词表里**。同样的哈希、同样的大小写，只要原文不在你算过的范围内，
再大的表也查不到——这就是加密盐存在的原因，也是 CMD5 这类网站按查询次数收费的原因。

关于「为什么哈希不可逆」，可以用三句话概括：

1. **信息被丢弃**——任意长度输入压成固定 256 位，多出来的信息已经不在结果里；
2. **多对一**——无限输入映射到有限输出，必然有天文数字个输入共享同一个哈希；
3. **反向无解**——把每轮运算写成方程，未知数远多于方程，解不唯一甚至不存在。

所以破解读取的真实路径永远是「**猜 → 正向算 → 比对**」，而不是「反推」。
agent 的说明文案里内置了这条提醒，就是防止使用者误解。

## 审计日志

每次对话都会追加一行 JSON 到 `agent_audit.log`：

```json
{"ts": "2026-10-06 17:39:32", "input": "校验 hello.txt", "action": "verify", "ok": true, "result": "{'MD5': 'f600dbfe...', ...}"}
```

| 字段 | 含义 |
|---|---|
| `ts` | 时间戳 |
| `input` | 用户原始输入 |
| `action` | 实际执行的动作 |
| `ok` | 是否成功 |
| `result` | 结果摘要（截断至 120 字符） |

**取证意义**：取证工作要求操作可追溯、可复核。日志记录了「谁在什么时候、基于什么输入、
做了什么操作、得到什么结果」——这就是保管链（chain of custody）的基本要素。
该文件默认不纳入版本控制（见 `.gitignore`）。

## 常见问题

**Q：为什么需要两个文件？能合成一个吗？**

`toolkit.py` 是干活的（纯函数库），`agent.py` 是决策和交互的。分开的好处是：
工具箱可以独立使用（`python toolkit.py demo samples`），agent 也能专注于理解与编排。
如果希望单文件分发，把 toolkit 的内容粘进 agent 并删掉 import 行即可。

**Q：为什么不接 LangChain 之类的框架？**

本项目工具只有 8 个、单轮指令为主、审计与降级要求明确。框架能省下的只是「调 API + 拼 prompt」
那部分样板代码，而白名单、审计、降级、对照表这些真正要紧的部分框架并不提供。
框架的抽象税大于收益时，手写循环更清晰也更好维护。
当工具数量变成几十个、需要多轮自主规划与 RAG 检索时，再考虑引入。

**Q：中文乱码怎么办？**

```powershell
$env:PYTHONIOENCODING = "utf-8"
```

**Q：`python` 命令找不到？**

用绝对路径调用，例如 `& "C:\Python312\python.exe" agent.py`。

**Q：本地模型响应很慢？**

9B 量化模型在普通显卡上单次意图解析约 1~5 秒；首次加载模型需 10~30 秒。
可换更小的模型（如 3B~4B）提升速度。

**Q：支持 Mac / Linux 吗？**

代码只用标准库，路径用 `os.path` 拼接，理论上跨平台可用；本项目在 Windows 上开发验证。

## 安全与合规

本项目是**教学与防御性研究**材料。使用前请确认：

1. **仅对授权样本操作**——你拥有或已获得书面授权的文件与哈希值；
2. **不处理未经授权的真实数据**——不做未授权系统入侵、不处理来源不明的涉案数据；
3. **接云端 API 时先脱敏**——发送给模型的本来就只是指令文本，不要额外把敏感数据写进指令；
4. **优先使用本地模型**——涉及敏感场景时，本地推理可以做到数据零外传；
5. **保留审计日志**——这是取证工作的基本要求，也是责任边界。

哈希碰撞演示、查表反查等功能用于理解算法弱点与防御手段，
**不得用于伪造证据、侵犯他人权益或任何违法用途**。
